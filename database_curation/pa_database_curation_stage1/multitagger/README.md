# MultiTagger scripts for the Pilot TF Meta-Assessment project

*Mary Beth Neff, University of Oslo, November 2026.*

*LLM transparency: this README was drafted with Claude (Anthropic, Opus 5.5) and reviewed by Mary Beth Neff.*

We used the pretrained MultiTagger-v2 model released with Menke et al. (2024; see *Model source*), a PubMedBERT-based multi-label classifier with 59 publication-type labels, to tag psychology articles by publication type. The labels were then mapped to empirical / non-empirical in R:
- `pilot2_db_multitagger-comparison._v2-public.R`: the Pilot 2 comparison with LLM classification. (Its input files, including the LLM classifications, were generated by `pilot2_db_curation_v5_replicable.R`.)
- `pilot-assessment_2025-db-curation_v2_public.R`: the Study 1 database. This script includes the MultiTagger steps: it writes the input file and reads the predictions back in.

This folder contains only the scripts we wrote. The model code and the trained model come from the MultiTagger-v2 authors and are downloaded separately (see *Setup*). They are not redistributed here. Everything was run from the Windows terminal (PowerShell), with files edited in Visual Studio Code.

### Our files

| File | Purpose |
|---|---|
| `run_multitagger_study1db.py` | Inference script used for Study 1. Use this for new runs. |
| `run_multitagger_pilot2db.py` | Earlier script, reconstructed for Pilot 2. Reproduces the Pilot 2 output, including its cut-off error; do not use for new runs (see *Earlier script version*). |
| `check_multitagger_labels.py` | Prints the model's labels and cut-offs (optional check). |

### Setup

1. **Get the model code.** Download the MultiTagger-v2 repository from https://github.com/ScienceNLP-Lab/MultiTagger-v2 (green **Code** button, then **Download ZIP**) and unzip it. The unzipped folder is called `MultiTagger-v2-main`. Only `AMIA/models/bert_model.py` is used; the other folders are not needed.
2. **Get the trained model.** Download it from the authors' Box link, https://uofi.box.com/v/multitagger-v2-model, into a folder named `best_verbalize_478k` inside `MultiTagger-v2-main`. Only `best_f1.mdl` (438 MB) and `best_thresholds.pkl` are needed.
3. **Add our scripts.** Copy the three files above into `MultiTagger-v2-main`.
4. **Create the Python environment.** In PowerShell, from `MultiTagger-v2-main`:
   ```
   python -m venv mt2env
   mt2env\Scripts\activate
   python -m pip install torch==2.11.0 transformers==5.8.0 pandas==3.0.2 numpy==2.4.4
   ```
   These are the versions we used (see *Software*). If PowerShell refuses to run `activate`, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once and try again.
5. **Create the input file and add it to the folder.** The scripts read a CSV of articles from `MultiTagger-v2-main`. These files are made by our R pipeline, not by this folder (details under *Input*):
   - **Study 1:** run `pilot-assessment_2025-db-curation_v2_public.R` up to the end of Step 3. It writes `articles_for_classification.csv`. Copy that file into `MultiTagger-v2-main`; `run_multitagger_study1db.py` reads it under that name by default.
   - **Pilot 2:** run `pilot2_db_curation_v5_replicable.R` through Step 3c. It writes `articles_abstracts_for_classification.csv`. Reformat it as described under *Input*, keep the same file name, and copy it into `MultiTagger-v2-main`. `run_multitagger_pilot2db.py` reads it under that name.
6. **Run the script** (see *Running*). It writes `multitagger_predictions.csv` into `MultiTagger-v2-main`.
7. **Return the predictions to R.** Copy `multitagger_predictions.csv` to the folder the R script reads it from (see the file paths in each script):
   - **Study 1:** `pilot-assessment_2025-db-curation_v2_public.R` reads the predictions back in and continues the curation.
   - **Pilot 2:** `pilot2_db_multitagger-comparison._v2-public.R` reads them and compares them with the LLM classification. The Pilot 2 curation script does not use the predictions.

After a run the folder looks like this. You only need the input for the study you are running.

```
MultiTagger-v2-main/
├── run_multitagger_study1db.py                 our inference script
├── run_multitagger_pilot2db.py                 reconstructed Pilot 2 script
├── check_multitagger_labels.py                 label check
├── AMIA/models/bert_model.py                   model class (from the repository)
├── best_verbalize_478k/                        trained model (from Box)
│   ├── best_f1.mdl                             checkpoint
│   └── best_thresholds.pkl                     the 59 labels, their order and per-label cut-offs
├── mt2env/                                     Python environment (step 4)
├── articles_for_classification.csv             Study 1 input, from the R curation script (step 5)
├── articles_abstracts_for_classification.csv   Pilot 2 input (step 5), only to re-run Pilot 2
├── prediction_parts/                           saved batches during a run; delete afterwards
└── multitagger_predictions.csv                 output, written by the script (step 6)
```

### Model source

The model is the pretrained release of Menke et al. (2024), linked from the repository's `AMIA/README.md`.
- The authors describe it as their best-performing configuration: PubMedBERT encoder, 80% undersampling of majority classes, verbalized metadata features and unsupervised contrastive loss.
- Our downloaded copy matches that release: `best_f1.mdl`, `best_thresholds.pkl`, the training log, validation and test predictions and performance, and `v1_aligned_*` results on the MultiTagger-v1 test set.
- We stored it as `best_verbalize_478k`, and the scripts expect that folder name. "478k" is not explained in the repository.

Citation:

> Menke JD, Kilicoglu H, Smalheiser NR. Publication Type Tagging using Transformer Models and Multi-Label Classification. *AMIA Annual Symposium Proceedings*. 2024.

### Software

- Python 3.11.9 (Microsoft Store build) with torch 2.11.0, transformers 5.8.0, pandas 3.0.2 and numpy 2.4.4. Versions were read from the environment used for both runs. Other recent versions will probably work but have not been tested.
- An internet connection on the first run: `transformers` downloads the PubMedBERT tokenizer and base model (about 440 MB) from Hugging Face. The script builds the model from it and then loads the trained weights from `best_f1.mdl`. A warning about `HF_TOKEN` can be ignored.
- No GPU needed. On a CPU, the Study 1 run (37,659 articles) took about 4 hours.

### Input

A CSV with one row per article, with at least:
- an article ID column. In the Pilot 2 file this is `pmid`, which holds the project's `article_id`, **not** a PubMed ID. In the Study 1 file it is `article_id`. The script does not use the ID; it is carried through to the output in the same row order.
- `abstract`: the text that is tagged. The column name is set by `TEXT_COLUMN` at the top of the script.

Our inputs:
- **Pilot 2:** `articles_abstracts_for_classification.csv` (24,911 articles).
- **Study 1:** `articles_for_classification.csv` (37,659 articles).

**Not shared publicly.** Neither the input files nor the prediction files are shared, because all of them contain full abstracts, which are usually copyrighted by the publishers. The inputs can be regenerated:

- **Pilot 2** (`articles_abstracts_for_classification.csv`):
  - It starts from the file of the same name written by `pilot2_db_curation_v5_replicable.R` in Step 3c: the 24,911 articles with usable abstracts, which are also the articles sent to the LLM (`articles_classified_all.csv` has the same articles and `article_id` values).
  - It was reformatted to the column layout the MultiTagger scripts expect, keeping the same file name:
    - `article_id` is renamed to `pmid`.
    - `doi`, `title`, `journal`, `abstract`, `year`, `volume`, `issue`, `pages` and `authors` are copied unchanged, with missing values written as blanks instead of "NA".
    - `journal` is also copied to `journal_title`, and `authors` to `author`.
    - `pub_date` and `pub_year` are set to the publication year (2023).
    - The remaining PubMed metadata columns (`pmcid`, `journal_issn`, `page_start`, `page_end`, `mesh`, `pub_type`, `affiliation`, `language`, `country`, `keywords`) are left empty.
  - Only the `abstract` column is used by the model. All other columns, including the ID, are carried through to the output.
- **Study 1** (`articles_for_classification.csv`):
  - Written by Step 3 of `pilot-assessment_2025-db-curation_v2_public.R` from the OpenAlex download, after record cleaning, PubMed abstract recovery, abstract checks and title screening.
  - Abstracts come from OpenAlex where available. Where OpenAlex had no usable abstract, it was taken from PubMed. The `abstract_source` column records which: 34,476 articles (91.5%) from OpenAlex and 3,183 (8.5%) from PubMed. Every article has an abstract and a DOI. ### What changed for Study 1

`run_multitagger_study1db.py` was rewritten from the earlier (Pilot 2) script in September 2026. The main changes:
- **Labels and cut-offs read from the model.** The label names, their order and the per-label cut-offs come straight from `best_thresholds.pkl`, instead of a hand-typed list. This fixes the cut-off error in the Pilot 2 predictions (see *Earlier script version*).
- **Staged autosave.** A full run takes hours on a CPU, so the script saves its results every 500 articles and can resume where it stopped (see *Running*). Each batch is written to a temporary file and only renamed once complete, so an interrupted run never leaves a half-written batch. The script also refuses to mix batches from runs with different settings.
- **Readable output.** One named column per label (0/1 and probability) plus a `predicted_types` summary, instead of two array columns.
- **Test mode and checks.** `TEST_ROWS` runs the first rows only; the script prints progress per batch and stops with a clear message if the text column is missing.
- **Model folder.** It loads from `best_verbalize_478k/` instead of `AMIA/models/best_model/` (the same model files).

### Running

In PowerShell, from the `MultiTagger-v2-main` folder:

```
mt2env\Scripts\activate
python run_multitagger_study1db.py
```

Settings are at the top of the script; there are no command-line options:
- input and output file names (defaults: `articles_for_classification.csv` and `multitagger_predictions.csv`)
- `TEXT_COLUMN` (default `abstract`)
- `TEST_ROWS`: set to a number (e.g. `50`) for a test run on the first rows; `None` runs the full file.

Results are saved every 500 articles in a `prediction_parts` folder. If the run stops, run the same command again: it skips the saved batches and continues. When all batches are done, they are joined into one output file. If you change the settings, delete `prediction_parts` first; the script stops and asks you to. Once the output has been checked, `prediction_parts` can be deleted.

### Output

The output is the input file with added columns:
- `predicted_types`: the labels assigned, e.g. "review; systematic_review". Empty if none were assigned ("no opinion").
- one 0/1 column per label: 1 if the label's probability is at or above that label's cut-off from `best_thresholds.pkl`. (The original repository code uses strictly above; the difference only matters if a probability equals a cut-off exactly.)
- one probability column per label.

This is the format the Study 1 curation script reads (one named column per label).

Probabilities are stored rounded to 4 decimals, but the 0/1 values were computed from the unrounded probabilities. Re-applying the cut-offs to the stored values can therefore differ in rare cases where a probability lies within 0.00005 of a cut-off (1 of about 2.2 million values in Study 1).

Our outputs (not shared; see *Input*):
- **Study 1:** `multitagger_predictions.csv` (37,659 rows, same order as the input, run 25 September 2026). 26.7% of articles received no label.
- **Pilot 2:** `multitagger_predictions.csv` (24,911 rows), in the older two-column format described under *Earlier script version*.

### Limitations

- **Abstract-only input.** The model was trained on verbalized PubMed metadata (journal, keywords, author and affiliation counts, chemicals and title, written out as sentences) followed by the abstract. Here it received the abstract only, which may lower accuracy relative to the published results. Some OpenAlex abstracts also begin with a stray "ABSTRACT" heading, which was not removed.
- **Domain shift.** The model was trained on biomedical PubMed articles; our articles are from psychology journals. In test runs, psychology experiments with random assignment were often tagged `clinical_trial`, `clinical_study` or `randomized_controlled_trial`.

### Labels: 59, read from the model

The model has 59 labels, in alphabetical order:
- `best_thresholds.pkl` stores them with one cut-off per label.
- `run_multitagger_study1db.py` reads the label names, their order and the cut-offs directly from that file, so they always match the model.
- `check_multitagger_labels.py` prints them for inspection.

This 59-label order is the same as `label_order` in both R scripts (checked November 2026).

### Earlier script version: the Pilot 2 predictions quirks

An earlier version of our script used a hand-typed list of 61 older label names and fuzzy-matched those names to the model's cut-offs. Its output was two array columns, `probabilities` and `predictions`, which is the format of the Pilot 2 output.

As found in September 2026, that version still had all 61 names and could not load the 59-label model, so the Pilot 2 run must have used an edited copy with 59 names, which was not kept. `run_multitagger_pilot2db.py` reconstructs it with the minimum edits that reproduce the stored output: `meta-analysis_as_topic` and `practice_guidelines_as_topic` removed, `NUM_LABELS` set to 59, and the Pilot 2 file names filled in. Its header lists these edits. Like the original, it loads the model from `AMIA/models/best_model/`; to re-run it, copy `best_f1.mdl` and `best_thresholds.pkl` there (or change `checkpoint_dir` and `threshold_file` at the bottom of the script to `best_verbalize_478k`). We kept the same two files in both folders, so Pilot 2 and Study 1 used the same model.

Because the 59-name list still contained `clinical_trials_as_topic`, the cut-offs were shifted by one position for labels 11–58: for example, `cohort_study` was judged against the cut-off of `clinical_studies_as_topic`, and `veterinary_observational_study` against that of `veterinary_clinical_trial`. In total, 47 of the 59 labels received the wrong cut-off. Labels 1–10, label 21 (`evaluation_studies_as_topic`, which lands on its own cut-off by coincidence) and label 59 (`veterinary_randomized_controlled_trial`) received their correct cut-off. This reproduces every one of the 24,911 Pilot 2 rows exactly (checked November 2026 against the stored probabilities, which are saved at full precision).

- **What was affected:** only the 0/1 values. The probabilities come straight from the model and are in the correct order.
- **How to fix it:** apply the correct cut-offs from `best_thresholds.pkl` to the stored probabilities. The model does not need to be re-run.
- **Effect:** 3,658 of the 24,911 articles (14.7%) have at least one label that changes. In the comparison with the LLM classification, overall agreement under rule A moves from 87.6% to 87.8%, and the share of articles with no label from 31.2% to 30.2%.
- **Not affected:** Study 1 predictions were made with `run_multitagger_study1db.py`, which reads the labels and cut-offs from `best_thresholds.pkl`.
